| --- | --- | --- | --- | --- |
| 1 | 2026-11-22 | Review plan PDF + CLAUDE.md, start Day 1 | Caught a real issue: ignore file was named `gitignore` (no dot), so Library/ and Temp/ would have been committed | Renamed to `.gitignore` before the first commit |
| 2 | 2026-11-22 | GameConfig data layer | Design choice to verify: outcome-first weights instead of per-reel random | Kept it: designers tune the chance of each outcome directly |

| 4 | 2026-11-22 | PlayerState + IServerApi + MockServer + GameBootstrap | First compile check failed: `JsonUtility` is in a separate module DLL (a reference issue in the outside-Unity check, not a code bug) | Compiled the scripts against Unity 6 DLLs outside the editor to verify them before opening Unity |
| 5 | 2026-11-22 | Unity console: CS0246 "IServerApi / PlayerSnapshot not found" | Code was fine (it compiled outside Unity). Logs/Editor.log showed Unity's compile list was missing ServerTypes.cs and IServerApi.cs: they were written while Unity was mid-refresh (folder is in OneDrive) and never imported | Two wrong fixes first: (a) Reimport, (b) I misread `PreviewImporter` log lines (only thumbnail generation) as the cause and deleted the metas; Unity restored the same GUIDs from its path cache. The real proof: the generated `Assembly-CSharp.csproj` didn't list those two files, so the asset DB had a stale entry for those paths. Fix: moved the code to new paths (`Server/Api/`, one type per file), which forces a fresh import. Lesson: verify the AI's diagnosis against hard evidence (compiler input list) before acting on it |
| 6 | 2026-11-22 | SpinController | Risk to check: an early idea was a client-side energy pre-check, which would be wrong with lazy server refill (stale client energy) | Server-only validation. Also removed GameBootstrap's debug spin because it skipped the events |
| 7 | 2026-11-22 | HudView, ReelView, SpinPanelView | First draft of ReelView used a fixed `new string[8]` buffer with `% length` indexing: it hid a mismatch instead of sizing to the real reel count. Views also read `CurrentBet` in OnEnable, which could run before SpinController.Awake | Sized the buffer from `reelLabels.Length` in Awake. Gave SpinController `DefaultExecutionOrder(-500)` (after bootstrap, before views) |
| 8 | 2026-11-24 | Village upgrade: no popups appeared | I checked the scene wiring (Popup Manager → Village Controller field) and the event code; both were correct, and the Console "2" was info logs, not errors. I asked for evidence instead of guess-fixing | **I** found it: re-ordering `PopupLayer` to the bottom had dropped it outside `Canvas`, so popups were queued and shown but never drawn. Re-parented it under Canvas. Lesson: when code and wiring check out, look at the scene hierarchy |
| 9 | 2026-11-24 | CoinFlyPool: MissingReferenceException when leaving Play mode | My `actionOnDestroy` assumed the coin still existed. I did not know Unity 6 tracks every `ObjectPool` and clears it on play-mode change (`PoolManager.Reset`), after the scene objects are already destroyed. The stack trace in Logs/Editor.log showed it | Null-check in `actionOnDestroy` (destroyed Unity objects equal null) and `pool.Clear()` in `OnDestroy`. Lesson: read the full stack trace, it named the engine system I did not know about |
| 10 | 2026-11-24 | Profile the coin pool (ON vs OFF) | My first measurement (whole-frame "GC Allocated In Frame") could not tell ON from OFF: Editor noise (~15 KB/frame) dwarfed the coins. My second (scoped `GC.GetAllocatedBytesForCurrentThread`) read 0 B even with pooling OFF, so the byte counter likely is not supported here | Kept only what the data supports: CPU -30% per burst and ~3.5x smaller worst-frame spike with pooling; memory benefit explicitly *not* claimed. Lesson: check a measurement can detect the effect before trusting it |
